# ChmlFrp 社区工具箱 Daemon 脚本托管与版本管理需求文档

> 本文档面向后端开发者，描述 Daemon 安装脚本和管理菜单脚本的后端托管、版本管理、管理后台上传、自动更新等完整需求。

## 一、背景

ChmlFrp 社区工具箱 Daemon 是部署在 Linux 服务器上的无图形界面服务，通过 WebSocket 中继与桌面客户端实现设备互联。

为方便用户安装和管理，提供两个 Shell 脚本：

| 脚本 | 用途 | 用户使用方式 |
|------|------|--------------|
| `install.sh` | 一键安装/卸载 Daemon | `curl -fsSL https://api.cct.zdzz.top/chmlfrp-toolbox-daemon/install.sh \| sudo bash` |
| `manage.sh` | 管理菜单（配置/启停/日志/卸载/更新） | `sudo chmlfrp-toolbox`（安装后）或 `curl -fsSL https://api.cct.zdzz.top/chmlfrp-toolbox-daemon/manage.sh \| sudo bash` |

**核心要求：**
1. 下载路径带项目名前缀（`/chmlfrp-toolbox-daemon/`），避免与其他项目冲突
2. 脚本由管理员通过管理后台上传，不直接读 GitHub
3. 支持版本管理：每次上传记录版本号、变更说明、时间戳、SHA256
4. 支持自动更新：脚本运行时可查询最新版本并自更新

## 二、接口总览

### 2.1 公开接口（无需鉴权）

| 方法 | 路径 | 用途 | 响应类型 |
|------|------|------|----------|
| GET | `/chmlfrp-toolbox-daemon/install.sh` | 下载最新版 install.sh | `text/x-shellscript` |
| GET | `/chmlfrp-toolbox-daemon/manage.sh` | 下载最新版 manage.sh | `text/x-shellscript` |
| GET | `/chmlfrp-toolbox-daemon/install.sh/info` | 查询 install.sh 最新版本信息 | JSON |
| GET | `/chmlfrp-toolbox-daemon/manage.sh/info` | 查询 manage.sh 最新版本信息 | JSON |

### 2.2 管理员接口（需管理员鉴权）

| 方法 | 路径 | 用途 |
|------|------|------|
| GET | `/api/admin/scripts` | 列出所有脚本及最新版本 |
| GET | `/api/admin/scripts/:name/versions` | 查看某脚本的所有版本历史 |
| GET | `/api/admin/scripts/:name/versions/:version` | 查看某版本详情（含下载链接） |
| POST | `/api/admin/scripts/:name/upload` | 上传新版本脚本 |
| DELETE | `/api/admin/scripts/:name/versions/:version` | 删除某版本 |
| PUT | `/api/admin/scripts/:name/rollback/:version` | 回滚到指定版本（设为最新） |

> `:name` 取值：`install` 或 `manage`（对应 install.sh / manage.sh）

## 三、公开接口详细设计

### 3.1 下载脚本

**请求：**
```
GET https://api.cct.zdzz.top/chmlfrp-toolbox-daemon/install.sh
GET https://api.cct.zdzz.top/chmlfrp-toolbox-daemon/manage.sh
```

**响应要求：**
1. HTTP 200，Body 为脚本原文（纯文本，**非 JSON 包装**）
2. `Content-Type: text/x-shellscript; charset=utf-8`（或 `text/plain`）
3. 必须支持 HTTPS
4. 允许跨域（`Access-Control-Allow-Origin: *`）
5. 缓存策略：`Cache-Control: no-cache`（确保每次拿到最新版本）
6. 默认返回「最新版本」的脚本内容（由管理员通过上传/回滚指定）

**示例（Express）：**
```javascript
app.get('/chmlfrp-toolbox-daemon/:scriptName\.sh', async (req, res) => {
    // scriptName: install | manage
    const { scriptName } = req.params;
    const file = await getLatestScriptFile(scriptName); // 从存储读取最新版本文件
    if (!file) return res.status(404).send('脚本尚未上传');
    res.setHeader('Content-Type', 'text/x-shellscript; charset=utf-8');
    res.setHeader('Cache-Control', 'no-cache');
    res.setHeader('Access-Control-Allow-Origin', '*');
    fs.createReadStream(file.path).pipe(res);
});
```

### 3.2 查询脚本版本信息

**请求：**
```
GET https://api.cct.zdzz.top/chmlfrp-toolbox-daemon/install.sh/info
GET https://api.cct.zdzz.top/chmlfrp-toolbox-daemon/manage.sh/info
```

**响应（JSON）：**
```json
{
  "success": true,
  "data": {
    "name": "manage",
    "version": "1.0.0",
    "changelog": "新增检查更新功能",
    "updatedAt": "2026-08-07T15:30:00.000Z",
    "size": 15360,
    "sha256": "a1b2c3d4...",
    "downloadUrl": "https://api.cct.zdzz.top/chmlfrp-toolbox-daemon/manage.sh"
  }
}
```

**字段说明：**
| 字段 | 类型 | 说明 |
|------|------|------|
| name | string | 脚本名（`install` / `manage`） |
| version | string | 版本号（语义化版本，如 `1.0.0`） |
| changelog | string | 变更说明（上传时填写） |
| updatedAt | string | 上传时间（ISO 8601） |
| size | number | 文件大小（字节） |
| sha256 | string | 文件 SHA256 校验值 |
| downloadUrl | string | 下载地址 |

> 此接口供 manage.sh 启动时调用以检查自身更新，必须返回 JSON 格式。

## 四、管理员接口详细设计

> 所有管理员接口需校验管理员登录态（沿用现有管理后台鉴权中间件）。

### 4.1 上传新版本脚本

**请求：**
```
POST https://api.cct.zdzz.top/api/admin/scripts/:name/upload
Content-Type: multipart/form-data
```

**表单字段：**
| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| file | File | 是 | 脚本文件（.sh） |
| version | string | 是 | 版本号（如 `1.0.0`，需符合语义化版本） |
| changelog | string | 否 | 变更说明 |

**响应：**
```json
{
  "success": true,
  "data": {
    "name": "manage",
    "version": "1.0.0",
    "changelog": "新增检查更新功能",
    "size": 15360,
    "sha256": "a1b2c3d4...",
    "uploadedAt": "2026-08-07T15:30:00.000Z",
    "isLatest": true
  }
}
```

**业务规则：**
1. 同一脚本同一版本号不可重复上传（返回 409 Conflict）
2. 上传后自动设为「最新版本」
3. 自动计算 SHA256 和文件大小
4. 文件内容需校验：首行须为 `#!/bin/bash`（防止上传非脚本文件）
5. 文件大小限制：建议 1MB 以内
6. 存储路径建议：`/var/lib/toolbox-scripts/<name>/<version>.sh`

### 4.4 删除版本

**请求：**
```
DELETE https://api.cct.zdzz.top/api/admin/scripts/:name/versions/:version
```

**业务规则：**
1. 不允许删除「最新版本」（返回 400，提示先回滚到其他版本）
2. 删除后同时删除存储的文件
3. 删除最后一个版本时，`GET /chmlfrp-toolbox-daemon/<name>.sh` 应返回 404

**响应：**
```json
{ "success": true, "data": null }
```

### 4.5 回滚到指定版本

**请求：**
```
PUT https://api.cct.zdzz.top/api/admin/scripts/:name/rollback/:version
```

**业务规则：**
将指定版本设为「最新版本」，`GET /chmlfrp-toolbox-daemon/<name>.sh` 和 `/info` 接口立即返回该版本内容。

**响应：**
```json
{
  "success": true,
  "data": {
    "name": "manage",
    "latestVersion": "0.9.0",
    "rolledBackAt": "2026-08-07T16:00:00.000Z"
  }
}
```

## 五、数据模型建议

### 5.1 scripts 表（脚本版本记录）

| 字段 | 类型 | 说明 |
|------|------|------|
| id | INTEGER PK | 自增主键 |
| name | TEXT | 脚本名（`install` / `manage`） |
| version | TEXT | 版本号（如 `1.0.0`） |
| changelog | TEXT | 变更说明 |
| file_path | TEXT | 存储路径 |
| size | INTEGER | 文件大小（字节） |
| sha256 | TEXT | SHA256 校验值 |
| is_latest | INTEGER | 是否为最新版本（0/1） |
| uploaded_by | TEXT | 上传者（管理员 ID） |
| uploaded_at | TEXT | 上传时间（ISO 8601） |

**索引：**
- `UNIQUE(name, version)` — 同一脚本同版本号唯一
- `INDEX(name, is_latest)` — 快速查询最新版本

**唯一约束：** 每个脚本只能有一条 `is_latest=1` 的记录（通过事务保证）。

## 六、管理后台前端需求

管理后台需新增「脚本管理」页面，功能包括：

1. **脚本列表**：展示 install / manage 两个脚本的最新版本、版本数量、更新时间
2. **上传新版本**：表单包含版本号、变更说明、文件选择，提交后调用 `POST /api/admin/scripts/:name/upload`
3. **版本历史**：点击某脚本查看所有版本，支持下载、回滚、删除
4. **下载最新版**：提供「复制下载命令」按钮（如 `curl -fsSL https://api.cct.zdzz.top/chmlfrp-toolbox-daemon/manage.sh | sudo bash`）
5. **即时预览**：上传成功后显示版本号、SHA256、文件大小供校对

## 七、脚本行为说明

### 7.1 install.sh 行为

```
用户执行: curl -fsSL https://api.cct.zdzz.top/chmlfrp-toolbox-daemon/install.sh | sudo bash
                    │
                    ▼
        1. 检查 root 权限
        2. 检测系统架构（x64/arm64）
        3. 创建系统用户 chmlfrp-daemon
        4. 从 GitHub Releases 下载 deb 包
        5. dpkg -i 安装 deb 包
        6. 生成配置文件 /etc/chmlfrp-toolbox-daemon/config.toml
        7. 创建数据目录 /var/lib/chmlfrp-toolbox-daemon
        8. 下载 manage.sh 到 /usr/local/bin/chmlfrp-toolbox
           (从 https://api.cct.zdzz.top/chmlfrp-toolbox-daemon/manage.sh 下载)
        9. 交互式引导配置（后端地址、proxyToken、设备名）
       10. 启动 systemd 服务并设置开机自启
```

### 7.2 manage.sh 行为

```
用户执行: sudo chmlfrp-toolbox
                    │
                    ▼
        1. 检查 root 权限
        2. 检查是否已安装（未安装则引导一键安装）
        3. 进入交互菜单：
           1) 查看配置      2) 添加账号      3) 修改账号
           4) 删除账号      5) 修改后端地址  6) 测试连接
           7) 启动服务      8) 停止服务      9) 重启服务
          10) 查看运行状态 11) 查看日志     12) 卸载
          13) 检查更新（子菜单）
              ├─ 1) 检查管理菜单脚本更新
              │     调用 GET /chmlfrp-toolbox-daemon/manage.sh/info
              │     对比版本号，有新版则下载覆盖自身
              └─ 2) 检查 Daemon 二进制更新
                    查询 GitHub Releases 最新版本
                    有新版则引导执行 install.sh 更新
```

### 7.3 manage.sh 自更新流程

```
1. 读取本地版本号 SCRIPT_VERSION（脚本头部常量）
2. GET /chmlfrp-toolbox-daemon/manage.sh/info 获取最新版本
3. 版本比较（sort -V）
4. 若有新版本：
   a. 下载 /chmlfrp-toolbox-daemon/manage.sh 到临时文件
   b. 校验首行为 #!/bin/bash
   c. 覆盖 $0（通常是 /usr/local/bin/chmlfrp-toolbox）
   d. 提示用户重新运行
```

## 九、部署流程

### 9.1 首次部署

1. 后端实现上述接口（公开下载 + 版本信息 + 管理员 CRUD）
2. 创建数据库表 `scripts`
3. 管理后台新增「脚本管理」页面
4. 管理员上传 `install.sh` 和 `manage.sh` 的初始版本（v1.0.0）
5. 验证公开下载和版本信息接口正常

### 9.2 脚本更新流程

```
开发者修改 install.sh / manage.sh
        │
        ▼
修改 manage.sh 头部的 SCRIPT_VERSION 常量
        │
        ▼
提交到 GitHub 仓库（chmlfrp-toolbox-daemon/deploy/）
        │
        ▼
管理员登录管理后台 → 脚本管理 → 上传新版本
   （填写版本号、变更说明、选择文件）
        │
        ▼
立即生效（公开下载接口返回最新版本）
        │
        ▼
已安装的用户运行 sudo chmlfrp-toolbox → 13) 检查更新
   即可自动获取新版本
```

## 十、安全与注意事项

1. **公开接口无鉴权**：`/chmlfrp-toolbox-daemon/*.sh` 和 `*.sh/info` 无需鉴权，任何人可下载
2. **管理接口需鉴权**：`/api/admin/scripts/*` 必须校验管理员登录态
3. **文件校验**：上传时校验首行为 `#!/bin/bash`，防止上传恶意文件
4. **版本号格式**：必须符合语义化版本（`MAJOR.MINOR.PATCH`），便于 `sort -V` 比较
5. **SHA256 校验**：客户端可选用 SHA256 校验下载完整性
6. **缓存控制**：公开下载接口必须 `Cache-Control: no-cache`，避免 CDN 缓存旧版本
7. **文件大小限制**：建议单文件 1MB 以内
8. **存储隔离**：脚本文件存储路径不应可被直接 URL 访问（必须经过应用层返回）

## 十一、技术选型建议

- **存储**：文件存磁盘（如 `/var/lib/toolbox-scripts/<name>/<version>.sh`），元数据存数据库
- **数据库**：沿用现有 SQLite/MySQL
- **文件上传**：`multer`（Node.js）或同等中间件
- **SHA256**：`crypto.createHash('sha256')`
- **版本比较**：后端无需比较版本号，客户端用 `sort -V`；后端只需存储和查询

## 十二、其他说明

1. **脚本内容**：两个脚本均为纯 Bash，无外部依赖（除 curl/wget/systemctl）
2. **兼容性**：支持 Ubuntu 20.04+、Debian 11+、CentOS 8+（需用 `--local` 参数手动安装 rpm）
3. **架构支持**：x64 和 ARM64
4. **卸载**：`sudo chmlfrp-toolbox` 选 12，或 `curl -fsSL .../install.sh | sudo bash -s -- --uninstall`
5. **Daemon 二进制更新**：manage.sh 的「检查 Daemon 更新」直接查询 GitHub Releases，不走后端（避免后端额外维护版本）；如未来需要后端代理，可新增 `GET /api/daemon/version/latest` 接口
