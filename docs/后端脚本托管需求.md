# ChmlFrp 社区工具箱 Daemon 安装脚本托管需求文档

> 本文档面向后端开发者，描述 Daemon 一键安装脚本（`install.sh`）的后端托管与管理后台上传需求。

## 一、背景

ChmlFrp 社区工具箱 Daemon 是部署在 Linux 服务器上的无图形界面服务，通过 WebSocket 中继与桌面客户端实现设备互联。

为方便用户安装，提供一个 `install.sh` 一键安装脚本：

| 脚本 | 用途 | 用户使用方式 |
|------|------|--------------|
| `install.sh` | 一键安装/卸载 Daemon | `curl -fsSL https://api.cct.zdzz.top/chmlfrp-toolbox-daemon/install.sh \| sudo bash` |

**核心要求：**
1. 下载路径带项目名前缀（`/chmlfrp-toolbox-daemon/`），避免与其他项目冲突
2. 脚本由管理员通过管理后台上传，不直接读 GitHub
3. 上传即覆盖当前对外提供的脚本内容（无版本管理、无更新日志）
4. 安装后的管理全部由桌面客户端「设备管理」页面远程完成，不再提供 `manage.sh`

## 二、接口总览

### 2.1 公开接口（无需鉴权）

| 方法 | 路径 | 用途 | 响应类型 |
|------|------|------|----------|
| GET | `/chmlfrp-toolbox-daemon/install.sh` | 下载当前 install.sh | `text/x-shellscript` |

### 2.2 管理员接口（需管理员鉴权）

| 方法 | 路径 | 用途 |
|------|------|------|
| GET | `/api/admin/scripts/install/info` | 查询当前 install.sh 信息 |
| POST | `/api/admin/scripts/install/upload` | 上传/覆盖 install.sh |

## 三、公开接口详细设计

### 3.1 下载安装脚本

**请求：**
```
GET https://api.cct.zdzz.top/chmlfrp-toolbox-daemon/install.sh
```

**响应要求：**
1. HTTP 200，Body 为脚本原文（纯文本，**非 JSON 包装**）
2. `Content-Type: text/x-shellscript; charset=utf-8`（或 `text/plain`）
3. 必须支持 HTTPS
4. 允许跨域（`Access-Control-Allow-Origin: *`）
5. 缓存策略：`Cache-Control: no-cache`（确保每次拿到最新内容）
6. 未上传时返回 HTTP 404，Body 为纯文本提示「安装脚本尚未上传」

**示例（Express）：**
```javascript
const SCRIPT_PATH = '/var/lib/toolbox-scripts/install.sh';

app.get('/chmlfrp-toolbox-daemon/install.sh', (req, res) => {
    if (!fs.existsSync(SCRIPT_PATH)) {
        return res.status(404).send('安装脚本尚未上传');
    }
    res.setHeader('Content-Type', 'text/x-shellscript; charset=utf-8');
    res.setHeader('Cache-Control', 'no-cache');
    res.setHeader('Access-Control-Allow-Origin', '*');
    fs.createReadStream(SCRIPT_PATH).pipe(res);
});
```

## 四、管理员接口详细设计

> 所有管理员接口需校验管理员登录态（沿用现有管理后台鉴权中间件）。

### 4.1 上传/覆盖安装脚本

上传即覆盖，每次上传直接替换当前对外提供的脚本内容。

**请求：**
```
POST https://api.cct.zdzz.top/api/admin/scripts/install/upload
Content-Type: multipart/form-data
```

**表单字段：**
| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| file | File | 是 | 脚本文件（.sh） |

**响应：**
```json
{
  "success": true,
  "data": {
    "name": "install",
    "size": 12288,
    "sha256": "a1b2c3d4e5f6...",
    "uploadedAt": "2026-08-08T15:30:00.000Z"
  }
}
```

**业务规则：**
1. 上传即覆盖：新上传的脚本立即成为公开下载接口返回的内容
2. 自动计算 SHA256 和文件大小
3. 文件内容需校验：首行须为 `#!/bin/bash`（防止上传非脚本文件）
4. 文件大小限制：建议 1MB 以内
5. 存储路径建议：`/var/lib/toolbox-scripts/install.sh`（单文件覆盖，无需保留历史）

### 4.2 查询当前脚本信息

**请求：**
```
GET https://api.cct.zdzz.top/api/admin/scripts/install/info
```

**响应：**
```json
{
  "success": true,
  "data": {
    "name": "install",
    "size": 12288,
    "sha256": "a1b2c3d4e5f6...",
    "uploadedAt": "2026-08-08T15:30:00.000Z",
    "downloadUrl": "https://api.cct.zdzz.top/chmlfrp-toolbox-daemon/install.sh"
  }
}
```

**字段说明：**
| 字段 | 类型 | 说明 |
|------|------|------|
| name | string | 脚本名（固定 `install`） |
| size | number | 文件大小（字节） |
| sha256 | string | 文件 SHA256 校验值 |
| uploadedAt | string | 上次上传时间（ISO 8601） |
| downloadUrl | string | 公开下载地址 |

> 未上传时返回 `success: true, data: null`，前端据此显示「尚未上传」。

## 五、数据模型建议

由于采用单文件覆盖模式，无需数据库表存储版本历史。如需记录上传日志，可使用一张轻量表：

### scripts 表（可选，仅记录上传日志）

| 字段 | 类型 | 说明 |
|------|------|------|
| id | INTEGER PK | 自增主键 |
| name | TEXT | 脚本名（固定 `install`） |
| file_path | TEXT | 存储路径 |
| size | INTEGER | 文件大小（字节） |
| sha256 | TEXT | SHA256 校验值 |
| uploaded_by | TEXT | 上传者（管理员 ID） |
| uploaded_at | TEXT | 上传时间（ISO 8601） |

> 当前生效的脚本信息可直接从磁盘文件实时计算（size/sha256），uploaded_at 取最近一条记录。如不需要审计日志，此表可省略。

## 六、管理后台前端需求

管理后台需新增「脚本管理」页面，功能包括：

1. **当前状态展示**：展示 install.sh 的文件大小、SHA256、上次上传时间；未上传时显示「尚未上传」占位
2. **上传/覆盖**：表单包含文件选择，提交后调用 `POST /api/admin/scripts/install/upload`，上传成功后刷新状态
3. **复制安装命令**：提供「复制一键安装命令」按钮，内容为：
   ```
   curl -fsSL https://api.cct.zdzz.top/chmlfrp-toolbox-daemon/install.sh | sudo bash
   ```
4. **上传校对**：上传成功后显示 SHA256、文件大小供校对

## 七、安装脚本行为说明

### 7.1 install.sh 安装流程

```
用户执行: curl -fsSL https://api.cct.zdzz.top/chmlfrp-toolbox-daemon/install.sh | sudo bash
                    │
                    ▼
        1. 检查 root 权限
        2. 检测系统架构（x64/arm64）
        3. 创建系统用户 chmlfrp-daemon
           ├─ 检测容器/受限环境 → 降级以 root 运行
           ├─ 检测 groupadd/useradd 命令是否存在 → 缺失则降级 root
           └─ 创建失败 → 降级 root（不中断安装）
        4. 从 GitHub Releases 下载 deb 包
        5. dpkg -i 安装 deb 包（依赖缺失自动 apt-get install -f 修复）
        6. 生成配置文件 /etc/chmlfrp-toolbox-daemon/config.toml
        7. 创建数据目录 /var/lib/chmlfrp-toolbox-daemon
        8. 若降级为 root 运行，自动修补 service 文件的 User=/Group= 行
        9. 交互式引导配置（后端地址、proxyToken、设备名）
       10. 启动 systemd 服务并设置开机自启
```

### 7.2 容器/受限环境适配

脚本内置三级降级策略，确保在大多数环境下可正常安装：

1. **容器检测**：通过 `/.dockerenv`、`/proc/1/cgroup`、`systemd-detect-virt` 识别 Docker/LXC/Podman/OpenVZ 等容器环境，直接以 root 运行
2. **命令缺失检测**：系统缺少 `groupadd`/`useradd` 命令时降级 root
3. **创建失败降级**：`groupadd`/`useradd` 执行失败（如权限受限）时降级 root，不中断安装

降级为 root 后，脚本会自动修补 `/etc/systemd/system/chmlfrp-toolbox-daemon.service` 中的 `User=` 和 `Group=` 行为 `root`，确保 systemd 服务能以 root 启动。

### 7.3 卸载

```
curl -fsSL https://api.cct.zdzz.top/chmlfrp-toolbox-daemon/install.sh | sudo bash -s -- --uninstall
```
或本地执行：
```
sudo bash install.sh --uninstall
```

卸载会停止并禁用服务、删除二进制、配置目录、service 文件，并在非 root 降级模式下清理创建的用户/组。数据目录会询问是否删除。

## 八、验收标准

### 8.1 公开下载接口

```bash
# 测试下载 install.sh
curl -fsSL https://api.cct.zdzz.top/chmlfrp-toolbox-daemon/install.sh | head -1
# 预期：#!/bin/bash

# 测试 Content-Type
curl -I https://api.cct.zdzz.top/chmlfrp-toolbox-daemon/install.sh | grep -i content-type
# 预期：text/x-shellscript 或 text/plain
```

### 8.2 管理员上传接口

```bash
# 上传 install.sh（需管理员 token）
curl -X POST https://api.cct.zdzz.top/api/admin/scripts/install/upload \
  -H "Authorization: Bearer <admin-token>" \
  -F "file=@install.sh"
# 预期：返回 success: true，含 size / sha256 / uploadedAt

# 上传非脚本文件应失败
echo "not a script" > bad.txt
curl -X POST https://api.cct.zdzz.top/api/admin/scripts/install/upload \
  -H "Authorization: Bearer <admin-token>" \
  -F "file=@bad.txt"
# 预期：HTTP 400，提示首行须为 #!/bin/bash
```

### 8.3 端到端验证

```bash
# 1. 管理员上传 install.sh
# 2. 在干净 Ubuntu 上执行一键安装
curl -fsSL https://api.cct.zdzz.top/chmlfrp-toolbox-daemon/install.sh | sudo bash
# 3. 验证安装
which chmlfrp-toolbox-daemon   # /usr/bin/chmlfrp-toolbox-daemon
sudo systemctl status chmlfrp-toolbox-daemon   # active (running)
# 4. 在容器环境（如 LXC/Docker）执行，应自动降级 root 并成功安装
```

## 九、安全与注意事项

1. **公开接口无鉴权**：`/chmlfrp-toolbox-daemon/install.sh` 无需鉴权，任何人可下载
2. **管理接口需鉴权**：`/api/admin/scripts/install/*` 必须校验管理员登录态
3. **文件校验**：上传时校验首行为 `#!/bin/bash`，防止上传恶意文件
4. **SHA256 校验**：客户端可选用 SHA256 校验下载完整性
5. **缓存控制**：公开下载接口必须 `Cache-Control: no-cache`，避免 CDN 缓存旧版本
6. **文件大小限制**：建议单文件 1MB 以内
7. **存储隔离**：脚本文件存储路径不应可被直接 URL 访问（必须经过应用层返回）

## 十、部署流程

1. 后端实现上述接口（公开下载 + 管理员上传/查询）
2. 管理后台新增「脚本管理」页面
3. 管理员上传 `install.sh` 初始版本
4. 验证公开下载接口正常返回脚本内容
5. 在干净 Linux 环境及容器环境分别验证一键安装可用

## 十一、其他说明

1. **脚本内容**：install.sh 为纯 Bash，无外部依赖（除 curl/wget/systemctl）
2. **兼容性**：支持 Ubuntu 20.04+、Debian 11+、CentOS 8+（需用 `--local` 参数手动安装 rpm）
3. **架构支持**：x64 和 ARM64
4. **容器适配**：自动检测 Docker/LXC/Podman/OpenVZ 等环境，降级以 root 运行
5. **Daemon 二进制更新**：通过桌面客户端「设备管理」页面远程触发检查更新，不走本后端
